## Where we stand, in one paragraph

We have genuine parity on the moments that make Lovable loved — prompt→live
preview, click-to-edit, one-click hosting with a shareable link, version
rollback, plan mode, error→fix, image input, remix — and we're structurally
ahead on the #1 complaint category (credit anxiety: we're free), on
ownership (MIT, export, lineage), and on context (commons, place, studio).
The two real gaps for our audience: **built apps have no user accounts**
⟪shipped since — see August update⟫ (Lovable Cloud gives every app
auth+DB+storage with zero config; our Community Cloud is a public JSON
store), and **our first five minutes have three gates** ⟪reworked since —
passcode retired⟫ (passcode → magic link → allowlist) where Lovable has
zero — including a dead-end for invitees not yet on the community allowlist.

## What users love about Lovable → us

## Field table stakes (Bolt/v0/Replit/Base44/Mocha) — checklist

Have: browser preview ✔ · no-card free tier ✔ (truly free, not demo-sized) ·
one-click deploy ✔ · checkpoints ✔ · error auto-fix ✔ · plan mode ✔ ·
GitHub export ✔ · agent narration ✔ · design-from-image ✔.
Partial/missing: idea/template library ◐ (4 prompt chips, no working
starters) · integrated per-app backend ◐ · mobile apps (Expo/QR) ✘ (skip —
web-first fits neighborhood tools) · Figma import ✘ (skip) ·
start-from-spreadsheet ✘ (interesting later — local orgs live in Sheets).

## Where the field's users get stuck → how exposed are we

1. **Error-fix loops** (the #1 killer everywhere): mitigated — no-retry rule,
   full-file fallback, one-click fix, and free means loops don't burn money.
2. **Runaway billing** (#1 quit reason): structurally avoided — subsidized,
   daily token caps instead of surprise charges.
3. **The last 30%**: same as everyone; our scope (small neighborhood tools,
   commons patterns) shrinks it but doesn't remove it.
4. **Auth/user accounts**: exposed — see gap #1 below.
5. **API keys/integrations**: Services tab + env guidance helps; Mocha's
   guided key prompts are the pattern to steal eventually.
6. **Deployment ≠ done**: good (env.js across preview/zip/deploys, tested).
7. **Lock-in anxiety**: strongest in field.
8. **No human support**: pilot-scale advantage — humans@ email, real people.

## The big remaining gaps, ranked

1. ⟪shipped⟫ **Neighbor accounts for built apps.** Email-code sign-in,
   member-stamped documents, visibility rules — live on Community Cloud,
   with export/backups/restore added August 2026.
2. ⟪reworked⟫ **First-run gates.** The passcode is retired; the front door
   is request-an-account → steward one-click approval → magic link. Fewer
   gates, no dead-end; still invitation-shaped on purpose.
3. **Starter gallery.** One-click working starter apps curated from the
   commons (calendar, lending library, phone tree, mutual-aid board) instead
   of prompt chips — the field's answer to blank-page paralysis, and ours
   can carry lineage. **Still the top open gap.**
4. **Design system for generated apps.** A house style (fonts/palette/
   components, 2–3 themes) woven into the build prompt so first outputs look
   proud-worthy without iteration. (The RB kit + plan-mode design briefs
   cover part of this; themes don't exist yet.)
5. ⟪specced⟫ **Custom domains on Community Hosting** — see
   `CUSTOM-DOMAINS.md`; ~3 days of code behind two owner decisions.
6. **Real-time co-editing** (known; last-save-wins today; own session).
7. Longer-tail: richer site analytics, guided API-key flows,
   start-from-Google-Sheet, PWA guidance for phone-friendly tools.

## Deliberate non-goals (don't chase)

Credits/billing machinery, SOC2/SSO/audit logs, Figma import, native mobile
apps, security-scan dashboards, 70-integration marketplace — enterprise or
scale features that don't serve a hundred neighbors and a free tool.

## Our unfair advantages (lean in)

Free without credit anxiety · commons knowledge in every chat · place-
grounded profiles · studio frames · neighbor notes (a return channel no
competitor has) · lineage + no enclosure · human support at the speed of
invitation.
